# Allur twin 2.0

Версия 2.0.0. Готовая установка для Docker с Linux-контейнерами, архитектура x86-64 (linux/amd64).

## Запуск

Распакуйте архив в постоянную папку. Установите и запустите Docker Engine или Docker Desktop с Docker Compose v2.

На Windows в PowerShell: `./start.ps1`. На Linux: `sh ./start.sh`.

Скрипт проверяет SHA-256 архива образов, выполняет `docker load`, создаёт уникальные секреты и запускает PostgreSQL, API, веб-интерфейс и резервное копирование. Сборка и скачивание основных образов не нужны. Образы не содержат базу клиента, пароли и загруженные файлы.

Адрес новой установки: **http://localhost:8088**. Первый вход: `admin`, пароль находится в локальном файле `.secrets/bootstrap_password`; после входа приложение требует сменить пароль.

Если порт занят, до запуска создайте `.env` с `PORT=8093` и `COOKIE_SECURE=false` на отдельных строках. Для нескольких клиентов добавьте уникальное `COMPOSE_PROJECT_NAME=allur-client-name` в каждую `.env` и назначьте разные порты. Имя проекта определяет том базы: не меняйте его у действующей установки без переноса данных.

Установка доступна на локальном компьютере. Для сети компании настройте HTTPS по `docs/OPERATIONS.md` и `compose.production.yaml`; образ Caddy скачивается отдельно. Для доступа извне нужны действующий домен, правила сети и сертификат.

## Локальный ИИ

Выполните `./start-ai.ps1` на Windows после основного запуска. Ollama и веса qwen3:4b скачиваются отдельно и не включены в images.tar. Начальная загрузка требует интернета. После загрузки сервер ИИ работает во внутренней сети Docker с `OLLAMA_NO_CLOUD=1`; производственные данные не отправляются внешнему провайдеру ИИ. На Linux следуйте разделу локального ИИ в исходниках и `docs/MANUFACTURING_AND_AI.md`.

Физическое управление по умолчанию отключено. Для подключения оборудования нужны реальные контроллеры, их протоколы, карта сигналов и HTTP-шлюз из исходного проекта. Эмуляция роботов и конвейера работает сразу, без подключения оборудования или модели ИИ.

## Полный учебный стенд SCADA

В **Автоматизации** открываются три участка: **Сварка**, **Окраска**, **Сборка**. В каждом доступны характеристики участка, роботы, оборудование, ТО и события его узлов. Привязка оборудования меняется в его карточке; общий склад сохраняется для всей установки. Подробности — в `docs/AUTOMATION_AND_THEMES.md`.

Переключатель светлой и тёмной темы находится в верхней панели и на экране входа. Выбор сохраняется в браузере. Основной цвет — синий; норма обозначается зелёным, предупреждение — жёлтым, риск и авария — красным.

Откройте **Оборудование и ТО → Эмуляция**. Здесь находятся четыре робота и конвейер, 107 узлов с датчиками, 11 сценариев неисправностей, прогноз ТО, учебный каталог из 28 позиций, заказы с поступлением по модельному времени, внутренние уведомления и ассистент. Детали схем выбираются мышью или клавиатурой. Действия и состояние сохраняются в базе; фактический склад предприятия ведётся отдельно.

В разделе **Локальный ИИ** выберите источник **Эмуляция SCADA**, чтобы анализировать стенд настоящей локальной моделью. Физические команды из этого режима недоступны. Перечень перенесённых функций и отличий от архива находится в `docs/SCADA_PARITY.md`.

## Остановка и данные

Остановка: `docker compose stop` (Windows: также `./stop.ps1`). Повторный запуск без загрузки архива: `docker compose up -d --pull never --wait web backup`.

Состояние хранится в постоянном томе PostgreSQL. Резервные дампы автоматически записываются в `backups` каждые 6 часов. Ручной дамп: `./backup.ps1`; проверка восстановления в отдельной базе: `./restore-check.ps1 -Backup <путь_к_dump>`.

Перед обновлением сохраняйте дамп, `.env` и `.secrets`. Не удаляйте тома базы. Перенос только папки с приложением не переносит содержимое тома PostgreSQL — восстановите дамп по инструкции эксплуатации.

## Комплект

- `images.tar` и `images.tar.sha256` — образы API 2.0.0, Web 2.0.0 и PostgreSQL 17.6.
- `compose.yaml`, скрипты и `docker` — запуск и обслуживание.
- `docs/Allur twin 2.0 - Характеристика приложения.docx` — полная характеристика.
- `docs/SCADA_FULL_VERIFICATION.md` — проверка полного переноса SCADA; `docs/RELEASE_2_0.md` — история первоначальной сборки.
- `docs/AUTOMATION_AND_THEMES.md` — участки и темы; `docs/AUTOMATION_THEME_VERIFICATION.md` — проверки этого обновления.
- `Allur-twin-2.0-source.zip` — исходники, образцы данных и автоматические проверки.
- `manifest.json` — состав и контрольные суммы файлов.

Комплект предназначен для новой установки. Обновление уже существующего проекта должно сохранять его имя Compose, секреты, настройки и тома.
