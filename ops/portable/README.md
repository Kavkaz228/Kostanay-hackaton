# Allur Twin — полный комплект Docker

Версия приложения **2.0.0**, сборка **2026-10-08**, платформа **Linux x86-64 / amd64**. Комплект включает приложение, PostgreSQL, локальный ИИ Ollama, веса **qwen3:4b**, Caddy для дополнительного HTTPS-развёртывания, исходники и документацию. Для первого локального запуска скачивать образы или модель не требуется.

## Быстрый запуск

1. Установите Docker Desktop с Linux-контейнерами либо Docker Engine и плагин Docker Compose (команда `docker compose`). Комплект проверен на Docker Engine 29.6.2 и Docker Compose v5.3.1. Рекомендуется выделить Docker не менее 12 ГБ RAM и 6 CPU; для комфортной работы локальной модели предпочтительны 16 ГБ RAM на компьютере. Оставьте не менее 30 ГБ свободного места для архива, распаковки, Docker-образов, модели и начальных данных. Видеокарта не обязательна.
2. Полностью распакуйте ZIP в постоянную папку с правом записи. Запускать скрипты прямо внутри ZIP нельзя. FAT32 не подходит: архив превышает ограничение размера файла 4 ГБ.
3. Windows PowerShell: `powershell -ExecutionPolicy Bypass -File .\start.ps1`. Linux: `sh ./start.sh`.
4. Откройте **http://localhost:8088**. Логин: **admin**. Случайный пароль новой установки лежит в `.secrets/bootstrap_password`; откройте файл локально. После первого входа приложение требует сменить пароль.

Скрипт проверит контрольные суммы, импортирует отсутствующие версии образов, создаст уникальные секреты, импортирует модель в отдельный том и запустит `db`, `api`, `web`, `backup`, `ollama`. Первая установка и проверка больших файлов могут занять несколько минут. Скорость ответа ИИ зависит от процессора; превышение тайм-аута видно в интерфейсе, измеренные данные при этом остаются доступными.

Если порт 8088 занят, **до первого запуска** скопируйте `.env.example` в `.env` и измените `PORT=8094`. Для нескольких установок задайте разные `COMPOSE_PROJECT_NAME` и порты. Имя по умолчанию — `allur-twin-portable`. Оно определяет тома базы и модели: у действующей установки не меняйте его без осознанного переноса данных.

Не используйте имя проекта `allur-twin` для независимой новой установки, если исходный проект уже работает на этой машине.

## Что открыть в приложении

- **Обзор / Симуляция линии** — выпуск, план, очередь, качество и модельное производство.
- **Автоматизация / Оборудование и ТО** — участки, учебный стенд SCADA, оборудование, обслуживание, учебный склад и сценарии неисправностей.
- **Локальный ИИ** — выбор источника: симуляция линии, учебный стенд SCADA или заводские данные. Ответ содержит фактические показатели, основания отклонений и предложения проверок. Учебные показания явно отличаются от заводских.
- **Мониторинг роботов** — контроль поступившей телеметрии, настраиваемых порогов, кодов ошибок и свежести данных; внутренние уведомления, принятие в работу, история и рекомендации ИИ.

Новая установка не содержит телеметрии предприятия. Для реального мониторинга подключите источник данных и настройте пороги конкретного оборудования. Физическое управление по умолчанию выключено. ИИ не отправляет команды оборудованию.

## Остановка, повторный запуск и сохранность

Windows: `.\stop.ps1`; Linux: `sh ./stop.sh`. Повторный запуск — тем же `start`-скриптом. Уже установленные версии образов не импортируются заново, секреты не меняются, существующая модель не перезаписывается. Проверка целостности файлов выполняется при каждом запуске.

Быстрый запуск после успешной установки: `docker compose --profile ai up -d --pull never --wait web backup ollama`. Для переимпорта отсутствующих файлов модели используйте `start.ps1` / `start.sh`; `start-ai` является совместимым псевдонимом полного офлайн-запуска.

Данные хранятся в томе PostgreSQL, модель — в отдельном томе Ollama. `.env`, `.secrets` и `backups` появляются только на машине получателя. Автоматические резервные копии создаются в `backups` каждые шесть часов. Ручная копия Windows: `.\backup.ps1`; проверка восстановления в отдельной базе: `.\restore-check.ps1 -Backup <файл.dump>`. Команды Linux и фактическое восстановление описаны в руководстве.

Не выполняйте `docker compose down -v` для действующей установки: эта команда удаляет тома. Для переноса нужны дамп PostgreSQL, `.env` и `.secrets`; одна папка приложения не содержит данные именованных томов. Сохраняйте секреты отдельно и передавайте их защищённым способом.

Комплект предназначен для новой установки. Обновление работающего экземпляра требует резервной копии, сохранения прежнего имени Compose, настроек, секретов и томов. Перед заменой приложения проверьте изменения на отдельной копии базы.

## Состав и проверка

- `images.tar` — API, Web, PostgreSQL, Ollama и Caddy; `images.metadata.json` фиксирует ID образов.
- `models/qwen3-4b.tar` — только манифест модели и необходимые blobs, без ключей идентичности Ollama.
- `source.zip` — полные исходники, Dockerfile, тесты, скрипты, образцы и документация.
- `gateway` — исходники отдельного шлюза для оборудования; его зависимости/драйверы и контроллеры подключаются отдельно.
- `docs` — полная документация и проверочные материалы.
- `manifest.json`, `SHA256SUMS`, отдельные `*.sha256` — контрольные суммы. На Linux: `sha256sum -c SHA256SUMS`.
- `licenses` и `docs/licenses` — уведомления и лицензии включённых компонентов/модели, где приложены; лицензии системных пакетов также входят в образы.

В комплекте нет рабочих паролей, `.env`, `.secrets`, пользовательской базы, её резервных копий и закрытых ключей Ollama. Контрольная сумма ZIP опубликована в соседнем файле `*.zip.sha256`.

## Доступ из сети и диагностика

По умолчанию веб-порт доступен только на локальном компьютере. Для сети предприятия настройте домен и HTTPS по полному руководству и `compose.production.yaml`. Образ Caddy включён; получение публичного TLS-сертификата требует доступа к удостоверяющему центру и правильно настроенного DNS/портов. Выполните после настройки: `docker compose -f compose.yaml -f compose.production.yaml --profile ai up -d --pull never --wait web backup ollama gateway`.

Состояние: `docker compose --profile ai ps`. Логи: `docker compose --profile ai logs --tail 100 api web ollama`. Проверка модели: `docker compose --profile ai exec -T ollama ollama list`. Если проверка SHA-256 не пройдена, распакуйте комплект заново; не отключайте проверку и не заменяйте рабочие секреты файлами другого экземпляра.
