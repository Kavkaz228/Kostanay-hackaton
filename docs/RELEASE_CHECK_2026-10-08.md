# Проверка поставки Allur Twin от 8 октября 2026 года

Версия приложения: **2.0.0**. Поставка: **Allur-Twin-2026-10-08-full-docker.zip**. Этот отчёт относится к текущему коду и переносимому комплекту; старые отчёты в `docs` описывают предыдущие проверки.

## Окружение и состав

- Windows, Docker Desktop с Linux-контейнерами; Docker Engine **29.6.2**, Docker Compose **5.3.1**.
- Платформа готовых образов: **linux/amd64**. Образы для ARM в комплект не входят.
- Пять готовых образов: API, Web, PostgreSQL 17.6, Ollama и Caddy. Точные ID и upstream digest записаны в `images.metadata.json` и `manifest.json`.
- `images.tar`: **4 018 279 424 байта**. Экспорт проверен фактическим `docker load`; ID всех пяти загруженных образов совпали с манифестом.
- `models/qwen3-4b.tar`: **2 497 310 720 байт**, ровно шесть файлов: манифест Qwen3:4b и пять необходимых blobs. Хеши blobs проверены. Ключи идентичности Ollama в архив не включены.
- Все 23 файла серверного приложения в образе API совпали по SHA-256 с текущими исходниками. После пересборки тестового образа также проверено совпадение 23 файлов приложения и 15 файлов тестов.

## Автоматические проверки

Серверные тесты актуального кода: **204 passed**, **223,19 секунды**, ошибок нет. Прогон выполнен после пересборки тестового образа и проверки совпадения его файлов с исходниками:

```powershell
docker compose -p allur-twin-check -f compose.yaml -f compose.test.yaml build tests
docker compose -p allur-twin-check -f compose.yaml -f compose.test.yaml run --rm --no-deps tests python -m pytest -q tests
```

Одно предупреждение относится к устаревающему использованию `httpx` в Starlette TestClient; на результат выполнения тестов оно не повлияло.

Браузерная проверка: **22 обычных сценария прошли**. В полном прогоне было 21 успешное выполнение и один конфликт слишком широкого локатора сообщения о сохранении качества. Локатор ограничен нужным экраном; повтор этого сценария прошёл. Два дополнительных сценария Ollama пропущены, поскольку не был включён `TEST_LOCAL_AI`; настоящая генерация отдельно проверена ниже. Изменение локатора включено в исходники поставки.

Проверка интерфейса выполнялась в отдельном Compose-проекте. Тесты не запускались на рабочей базе пользователя.

## Развёртывание готового комплекта

Создана отдельная копия каталога поставки с новым Compose-проектом `allur-release-check`, портом 8094, собственной базой, секретами и томом модели. В поставке этих проверочных данных нет.

Первый запуск штатного `start.ps1` занял **105,35 секунды**. Проверены контрольные суммы, созданы новые секреты, в пустой том импортированы шесть файлов модели. Сервисы `db`, `api`, `web`, `backup`, `ollama` перешли в состояние healthy. Запуск использовал готовые образы и `--pull never`, без скачивания модели.

Через HTTP выполнены вход новым администратором, обязательная смена временного пароля и повторная авторизация. Проверены:

- отсутствие заводских измерений у новой установки;
- доступность отдельных контекстов симуляции линии и учебного стенда;
- локальная модель в состоянии ready;
- запрет общего чтения API ключом интеграции;
- повтор приёма пакета с тем же ключом идемпотентности без дублирования измерений;
- превышение температурного порога: 85 °C при критической границе 80 °C;
- фоновое критическое уведомление с рекомендацией, принятие сотрудником и закрытие после нового измерения 45 °C;
- ровно два проверочных измерения, сохранённые настройки, история принятия и восстановления;
- отсутствие физических команд оборудованию.

Реальный запрос к **qwen3:4b** по данным R2 учебного стенда вернул показания и **две рекомендации**. Холодный запрос занял **121,69 секунды**. Это одно наблюдение на данном компьютере, а не гарантия производительности на другом оборудовании. Запрос был завершён моделью, предложение физической команды отсутствовало. Весь сценарий первоначальной HTTP-проверки занял 137,4 секунды.

Повторный полный запуск тем же `start.ps1` занял **89,59 секунды**. Контрольные суммы обоих установочных секретов и ID всех пяти контейнеров остались прежними, импорт модели добавил **0 файлов**. Повторная HTTP-проверка `--verify-existing` прошла: два измерения, настройки и закрытый инцидент сохранены, физических команд нет. Большая часть повторного запуска — проверка целостности поставки; повторной загрузки образов не было. Проверочный проект после работы остановлен, его тома сохранены отдельно.

## Перезапуск и резервная копия

После перезапуска API и Web проверка через HTTP подтвердила сохранность двух измерений, настроек робота и принятого/закрытого уведомления. Перезапуск с проверкой занял **15,62 секунды**.

Штатный `backup.ps1` создал дамп размером **32 356 байт** за **5,21 секунды**. `restore-check.ps1` восстановил этот дамп в отдельном контейнере PostgreSQL без сети, выполнил `pg_restore --exit-on-error` и прочитал таблицы снимков, истории и событий. Проверка восстановления заняла **13,16 секунды**; получены один снимок, одна запись истории и три события. Временный контейнер был удалён штатным проверочным скриптом.

Отдельные SQL-проверки `robot_observations` и `monitor_alert` после восстановления дампа не выполнялись. Их содержимое проверено через API до резервного копирования и после перезапуска приложения. Рабочая база пользователя при проверке восстановления не менялась.

## Документация и упаковка

Руководство включает 21 раздел: назначение, три источника данных, архитектуру, хранение, экраны, модель производства, импорт, мониторинг, ИИ, оборудование, склад и ТО, SCADA, роли, шлюз, Docker, обновление, копии, сеть, диагностику и разработку. Справочник API описывает **82 пути и 87 операций**; `openapi.json` получен из текущего приложения.

Автономные `PROJECT_MANUAL.html` и `API_REFERENCE.html` открыты в Chromium без сети при ширине 1440 и 390 px. Просмотрены снимки начала документа, схемы, раздела ИИ и API. Проверены отсутствие переполнения страницы, ошибочных внутренних якорей, ошибок JavaScript и внешних запросов. Широкие таблицы и схема имеют собственную горизонтальную прокрутку на узком экране.

Проверка исходного архива исключила `.env`, `.secrets`, рабочие и тестовые базы, резервные копии, закрытые ключи, результаты тестов и служебные маркеры проверки. Дополнительно выполнен поиск значений локальных установочных секретов в исходниках и вложенных XML существующего DOCX — совпадений нет. Учебные образцы данных остаются в `samples` и не загружаются в новую заводскую базу автоматически.

Финальный упаковщик обновляет исходники и документацию, вычисляет SHA-256 файлов, собирает ZIP64 и проверяет CRC всех его записей. Итоговая контрольная сумма ZIP находится в соседнем файле `*.zip.sha256`; контрольные суммы содержимого — в `SHA256SUMS` и `manifest.json` внутри комплекта.

## Границы проверки

Полный запуск выполнен на Windows с Linux-контейнерами Docker. Для POSIX shell-скриптов проверены синтаксис и окончания строк LF; отдельный полный запуск на Linux-хосте или ARM не проводился. Получение HTTPS-сертификата Caddy для настоящего домена, подключение заводских контроллеров и физическое управление не проверялись в этой поставке.

Это проверка установки и заявленных программных сценариев. Она не заменяет настройку порогов конкретного оборудования, проверку качества заводских данных, нагрузочное испытание площадки и оценку рекомендаций ИИ специалистом.
